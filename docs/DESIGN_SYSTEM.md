# AIMP Karaoke Studio — Design System v1.0

**Статус:** реализация в WPF; спецификация для последующих экранов и плагинов.
**Платформа:** Windows, .NET 10 / WPF, AIMP 5.40.
**Визуальное направление:** Focused Lyrics — плотная тёмная оболочка AIMP и минималистичный, почти сценический холст песенного текста.

## 1. Цель и продуктовые инварианты

Дизайн-система предотвращает визуальный дрейф: новые функции должны выглядеть как часть одного приложения, а не как независимые окна, собранные разными разработчиками. Каждое значение должно иметь семантический смысл, а не задаваться произвольным шестнадцатеричным кодом или отступом.

Система **не меняет** LRC/Enhanced LRC тайминги, алгоритм KaraokeHighlightEngine, виртуализацию списка, IPC, native AIMP API, онлайн-провайдеры перевода, горячие клавиши и параметры пользователя.

### Источники истины

| Область | Исходный файл | Правило |
|---|---|---|
| Цвета, шрифтовые размеры, шаги сетки, радиусы | `app/Styles/Tokens.xaml` | Единственный runtime-реестр визуальных токенов |
| Переиспользуемые WPF-стили и визуальные состояния | `app/Styles/Components.xaml` | Применять через `StaticResource` |
| Геометрия окон, брейкпоинты и ширина панели | `app/Design/DesignMetrics.cs` | Использовать и в XAML, и в code-behind |
| Экспорт для дизайн-инструментов | `docs/design-system/tokens.json` | Синхронизирован автотестом; не заменяет runtime-ресурсы |
| Контракты и контраст | `tests/design_system_checks.py` | Запускается в Windows CI |

В `App.xaml` последовательно импортируются `Tokens.xaml` и `Components.xaml`. Персональный акцент продолжает обновляться в рантайме через `DynamicResource`.

## 2. Сетка и размеры

Единица измерения — **DIP** (device-independent pixel). Базовый шаг — **4 DIP**.

| Токен | Размер | Назначение |
|---|---:|---|
| `DS.Space.1` | 4 | Микроотступ и расстояние внутри компактных компонентов |
| `DS.Space.2` | 8 | Интервалы между действиями, меткой и полем |
| `DS.Space.3` | 12 | Стандартная горизонтальная внутренняя область кнопки |
| `DS.Space.4` | 16 | Интервалы между связанными группами |
| `DS.Space.6` | 24 | Внешний отступ диалога, разделение секций |
| `DS.Space.8` | 32 | Крупный интервал между независимыми зонами |

| Конструктивный размер | DIP |
|---|---:|
| Titlebar | 40 |
| Верхний тулбар | 64 |
| Нижний transport | 64 |
| Settings drawer (desktop) | 320 |
| Стандартная кнопка / поле / ComboBox | 36 |
| Уплотнённое управление | 32 |
| Строка результата поиска (минимум) | 52 |
| Внешний gutter диалога поиска | 24 |
| Внутренний gutter настроек | 20 |

Радиусы: `Small=4`, `Control=6`, `Card=8`. Для панелей и кнопок базовая граница — 1 DIP; состояния фокуса **не изменяют толщину**, чтобы не смещать соседние элементы.

Исключения из сетки разрешены лишь при уважительной причине: граница 1 DIP, размеры шрифтов, индивидуальные timed lyric segments и оптическая корректировка иконки. Вся новая геометрия обязана обосновываться токеном.

## 3. Типографика

Основной шрифт интерфейса — встроенный `Segoe UI`. Временные метки — `Consolas` (моноширинные цифры).

| Уровень | Размер | Применение |
|---|---:|---|
| Caption | 10 | Чипы источников, подписи секций |
| Label | 11 | Вторичный интерфейс, справка |
| Body | 12 | Кнопки, настройки, результаты |
| Heading | 16 | Название панели / диалога |
| Display | 24 | Пустое состояние, не сценический текст |

Главная вокальная строка — **особый компонент**: размер пользовательский, по умолчанию 48 DIP; соседние строки и перевод подстраиваются под него согласно существующей логике `ApplyLineStyles()`. Для караоке запрещено заменять раздельные `HighlightedText` / `RemainingText` на единый TextBlock с обновлением на каждый кадр.

Длинные описания: `TextWrapping="Wrap"`, без обрезания; заголовки треков могут использовать `CharacterEllipsis`, но полное название должно оставаться доступным через контекст или в источнике данных.

## 4. Цветовые роли

Токены **семантические**: `WindowBrush`, `DrawerBrush`, `SurfaceBrush`, `TextBrush`, `SecondaryBrush`, `DimBrush`, `AccentBrush`, `FocusRingBrush`, `SelectionBrush`, `ErrorBrush` и др. Полная палитра находится в `Tokens.xaml` и JSON-экспорте.

Заложены следующие контрасты (вычислены по относительной яркости WCAG на фиксированных парах):

| Пара | Контраст |
|---|---:|
| Основной текст / фон окна | 16.32:1 |
| Вторичный текст / панель настроек | 9.66:1 |
| Приглушённый текст / сценический фон | 7.18:1 |
| Фокус / фон поля | 10.28:1 |

Данные пары достигают минимум 4.5:1; это **не** означает, что уже проверены все возможные комбинации и динамические акцентные темы. При смене пользовательского цвета требуется дополнительная оценка на экране.

Семантика цветовых ролей важнее выбора конкретного оттенка. Кнопка активного режима использует `AccentSurfaceBrush`, тексты — `TextBrush`, сквозные контуры — `StrokeBrush`. Выделенная строка списка использует `SelectionBrush` и левый accent-индикатор.

## 5. Библиотека компонентов

| Ключ стиля | Компонент | Состояния |
|---|---|---|
| `ChromeButton` | Общая кнопка | default, hover, pressed, focus, disabled |
| `OutlineButton` | Второстепенное действие | те же |
| `PrimaryButton` | Поиск и применение | те же, акцентная поверхность |
| `ModeButton` | Чтение / Караоке / Сцена | hover + selected в code-behind |
| `WindowControl` | Свернуть / развернуть / закрыть | 40×40, focus |
| `TransportButton`, `RoundPlay` | Транспорт | focus, hover, disabled |
| `SettingSlider` | Ползунки | единый трек/ползунок |
| `SettingCheck` | Опции | checked, hover, focus, disabled |
| `StudioTextBox` | Поля поиска / адреса | hover, keyboard focus, disabled |
| `StudioComboBox` + `StudioComboBoxItem` | Источники / языки | hover, keyboard focus, selected, disabled |
| `StudioCard` | Контейнер результатов / превью | поверхность, радиус, обводка |
| `StudioVerticalScrollBar` | Полоса прокрутки настроек и поиска | нейтральная тёмная дорожка, hover, dragging |
| `DiscoveryResultItem` | Результат поиска | hover, selected, focus |
| `PanelTitle`, `PanelLabel`, `HelperText` | Тексты | иерархия читаемости |

Стандартные интерактивные цели имеют высоту от 32 DIP; транспорт и основные поля — 36–40 DIP. Если компонент содержит значимый текст, нельзя уменьшать его высоту без теста на масштабирование шрифта Windows.

## 6. Адаптивность и иерархия

- **≥ 1100 DIP:** полные названия режимов, кнопок поиска и настроек.
- **980–1099 DIP:** сокращённые надписи команд, без потери функций.
- **< 980 DIP:** настройки переходят в правую overlay-панель с кликабельным затемнением холста.
- **< 880 DIP:** скрываются кнопки A− / A+ в транспортной панели, но Ctrl+± и Ctrl+колесо сохраняют доступ к масштабу.
- **Минимальное окно:** 710×480 DIP (сохранён исходный контракт).
- **Полный экран:** верхняя и нижняя оболочки скрыты, сценическое пространство сохраняет приоритет; при возврате используются те же структурные метрики.

Панель настроек — ширина 320 DIP. При сужении окна ниже порога overlay не уменьшаем рабочую сцену с текстом; вместо этого панель накладывается поверх с scrim. Клик по затемнению закрывает настройки. Кнопка закрытия и Esc остаются доступными.

Блок поиска использует пропорцию **5:7** между вариантами и предпросмотром с промежутком 16 DIP. Подписи полей, CTA и результаты строятся на компонентах из общей библиотеки. При минимальной ширине диалога проверяется перенос вспомогательных текстов и footer.

## 7. Interaction и доступность

- **Фокус** виден при навигации с клавиатуры и не изменяет размеры элемента.
- **Hover** отличается от **selected**: указатель не стирает текущий выбор.
- **Disabled** визуально ослаблен, но доступность кнопки определяется исходной бизнес-логикой.
- **Tooltip** дополняет сокращённые названия, не заменяя доступное имя действия.
- Основной текст песен остаётся виртуализированным: запрещено создавать отдельную scrollable-панель переводов.
- Не добавлять тяжёлых визуальных эффектов в per-frame рендеринг караоке.
- Не перекрывать транспортную панель overlay-настройками; настройки открываются в центральной области.
- Для существенных действий рекомендуется клавиатурный путь; особое внимание поиску, выпадающим спискам и применению текста.

## 8. Процедура изменения дизайна

1. Проверить, существует ли нужная семантическая роль в `Tokens.xaml`.
2. Добавить / расширить компонент в `Components.xaml`, не копировать локальный стиль окна.
3. Проверить `hover / pressed / focus / disabled / selected`.
4. Использовать конструктивные размеры из `DesignMetrics.cs`, если от них зависит code-behind.
5. Обновить `tokens.json` для изменённых токенов, поддержать автотесты.
6. Запустить `python tests/design_system_checks.py`, `python tests/source_contract_checks.py` и Windows CI.
7. Провести ручную визуальную QA по `docs/design-system/QA_MATRIX.md`.

**Граница гарантии:** статические проверки и Windows CI удостоверяют синтаксис ресурсов, компиляцию, контракт и автоматические сценарии. Фактическое отсутствие переполнений, качество рендеринга при DPI 100–200%, работу выпадающих списков и впечатление от экранов следует проверять визуально на установленной сборке.
